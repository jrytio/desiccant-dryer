# Display UI redesign — design

Date: 2026-09-14
Status: approved in conversation; awaiting spec review

## Goal

Replace the placeholder text screen on the 1.54" ST7789 (240×240, 8-bit
palette) with a process-schematic view of the dryer: two standing desiccant
cylinders with live temperature fills, the air path through the open valve,
heater state, per-pack phase and timer, outlet humidity against its
thresholds, case temperature, fan, and a status strip. Make the exact drawing
code runnable on the Mac so every state can be screenshotted without
hardware.

## Context and constraints

- Display: ST7789V over SPI, `color_palette: 8BIT` (fixed RGB 3-3-2; the
  16-bit buffer does not fit on the S2). Every colour is snapped to that
  grid at draw time; the design uses only grid colours so previews are
  honest. The adaptive palette is ruled out: it does a 256-entry search per
  drawn pixel.
- ESPHome 2026.1.4: `image:` rasterises SVG at compile time (resvg, a hard
  dependency, so CI has it), pulls `mdi:` icons by name, and stores images in
  flash. `font:` supports `gfonts://Family@weight` and 4-bit anti-aliasing.
  The `host` platform with the `sdl` display exists; SDL2 is installed on
  the Mac via Homebrew.
- Display update interval stays 2 s. Redraw is a full frame each time.
- All `CLAUDE.md` invariants stand. In particular the display must show
  "SIM" whenever the humidity override is active.

## Decisions made during brainstorming

| Question | Decision |
|---|---|
| Per-pack timer | Active pack: time in service. Standby pack: time in its current phase (new counter) |
| "Ambient" temperature | The case DS18B20 (`case_temp`) |
| Outlet humidity | Kept, as a three-zone threshold gauge, not a progress bar |
| Secondary states | Bottom status strip; red for fault; IP shown for the first 60 s after boot |
| Layout | Process schematic with standing cylinders, air path top to bottom (mockup "C1") |
| Plumbing shown | Common wet-air inlet at the top, one valve per pack on its outlet branch, sensor on the outlet manifold. No vent arrows |
| Phase colours | IN SERVICE green, HEATING orange, COOLING cyan, READY blue, WET grey |
| Rendering | SVG sprites for symbols, primitives for data, helper header for the C++ |
| Preview | Host build with an SDL window and a scenario table, screenshots committed |

Reference mockup: `docs/display/mockup-states.html` (twelve states, generated
during brainstorming; open in a browser).

## Non-goals

- Animation of any kind.
- Touch, buttons, or paging.
- Changes to thresholds, the state machine, or HA entities beyond the one
  new diagnostic sensor.
- Partial-redraw optimisation (the draw function is structured so it can be
  added later).

`display.yaml` keeps the `spi:`, backlight `output:`/`light:` and the
`display:` block. The display gets `id: lcd` and its lambda becomes
`id(ui_draw).execute();`. The `font:` and `color:` blocks move out (colours
become constants in the header).

`display-ui.yaml` holds `esphome: includes: [packages/display_ui.h]`, the
fonts, the images, and:

```yaml
script:
  - id: ui_draw
    mode: single
    then:
      - lambda: |-
          UiState s;
          s.active = id(active_pack); s.standby_state = id(standby_state);
          s.fault_code = id(fault_code); s.enabled = id(dryer_enabled).state;
          s.sim = id(sim_enabled).state; s.fan = id(case_fan).state;
          s.heater_a = id(heater_a).state; s.heater_b = id(heater_b).state;
          s.valve_a = id(valve_a).state;  s.valve_b = id(valve_b).state;
          s.t_a = id(pack_a_temp).state; s.t_b = id(pack_b_temp).state;
          s.t_case = id(case_temp).state; s.rh = id(ctrl_rh).state;
          s.arm_rh = id(arm_rh).state; s.swap_rh = id(swap_rh).state;
          s.cooldown = id(cooldown_temp).state; s.regen = id(regen_temp).state;
          s.overtemp = id(overtemp).state;
          s.service_s = id(service_elapsed_s); s.standby_s = id(standby_elapsed_s);
          s.status = id(status_text).state; s.fault_msg = id(fault_message).state;
          s.ip = id(ip_addr).state; s.uptime_ms = millis();
          UiAssets a{ id(f_temp), id(f_val), id(f_cap), id(f_label), id(f_phase),
                      id(f_status), id(f_status_b), id(img_bg), id(img_valve_open),
                      id(img_valve_closed), id(img_heater_on_a), id(img_heater_on_b), id(img_lit_a),
                      id(img_lit_b), id(img_fault_ring), id(img_cap_blue),
                      id(img_cap_amber), id(img_cap_gold), id(img_fan) };
          draw_ui(*id(lcd), s, a);
```

The script is the only place that touches ids, so the same drawing runs on
the ST7789 and in the SDL window. Executing a lambda-only `single` script
from inside the display lambda runs synchronously.

The header has no `id()` calls. It defines `UiState`, `UiAssets`, the
palette constants, small helpers (`draw_cylinder`, `draw_gauge`,
`draw_strip`, `fmt_timer`) and `draw_ui()`. Target size about 120 lines.

## 4. Draw order (every frame)

1. `fill(BLACK)`.
2. For each pack with a valid temperature: fill band rectangles from the
   level down to y 156, then the cap sprite at the level.
3. `img_bg`.
4. Valve sprites from the real `valve_a`/`valve_b` states; heater-on sprite
   from the real `heater_a`/`heater_b` states; lit path sprite for the pack
   whose valve is open (none if neither); fault ring if `fault_code != 0`.
5. Threshold dashes, text plates, temperatures, phase words, timers.
6. RH value, zone word, gauge zones and marker; CASE label and value; fan
   icon and label; SIM badge if active.
7. Status strip.

Sprites and lit paths reflect the actual output switches, not the state
machine, so the screen shows what the relays are doing.

## 5. Rules

**Palette** (all RGB 3-3-2 grid points):

| Name | Hex | Use |
|---|---|---|
| green | `#24DB55` | in service, open valve, lit path, fan on, DRY zone |
| orange | `#FF9200` | HEATING, fill band |
| amber | `#FFB600` | heater glow core, fill top band at/above regen, SIM badge, RISING/HIGH zone |
| deep orange / dark orange | `#DB4900` / `#B64900` | fill bottom band / glow halo, regen dash |
| cyan | `#00DBFF` | COOLING |
| blue / light blue / dark blue | `#246DFF` / `#4992FF` / `#0049AA` | READY, cool fill and cap, cooldown dash |
| grey shell | `#494955` | pipes, shells, off symbols, strip line |
| dim | `#9292AA` | WET, OFF, labels, closed valve outline, NaN values |
| strip text | `#B6B6AA` | status text |
| red | `#DB2424` (strip), `#FF2424` (FAULT word, OVER zone, fault ring) | faults |
| dim zones | `#246D24`, `#6D4900`, `#6D0000` | inactive gauge zones |

**Fonts** (Google Fonts, fetched at compile time):

| Id | Family/weight | Size | bpp | Glyphs |
|---|---|---|---|---|
| `f_temp` | Barlow 700 | 24 | 4 | `0123456789°-` |
| `f_val` | Barlow 600 | 12 | 4 | `0123456789.%°-hm RH` |
| `f_cap` | Barlow 700 | 11 | 4 | `AB` |
| `f_label` | Inter 600 | 8 | 4 | `A–Z` and space |
| `f_phase` | Inter 700 | 8 | 4 | `A–Z` and space |
| `f_status` | Inter 500 | 10 | 4 | printable ASCII plus `·` |
| `f_status_b` | Inter 700 | 10 | 4 | same set |

**Fill.** `frac = clamp((t − 20) / (overtemp − 20), 0, 1)`. Family by
temperature: at or below `cooldown_temp` two blue bands (`#246DFF` over
`#0049AA`) with the blue cap; above it orange bands (`#FF9200`, `#FF6D00`,
`#DB4900`) with the amber cap; at or above `regen_temp` an extra `#FFB600`
band on top and the gold cap. Bands split the fill height equally, minimum
6 px each. NaN: no fill, `--°` in dim.

**Phase words.** Active pack: IN SERVICE. Standby: WET, HEATING, COOLING,
READY from `standby_state`; FAULT (red) on the faulted pack. Disabled: OFF on
both, no timers. `active_pack == 0` while enabled: empty phase, no timers.
Faulted pack: code 1 is the active pack, codes 2 and 3 the standby pack.

**Timers.** Active pack: `service_elapsed_s`. Standby pack:
`standby_elapsed_s`. Format: `Hh MMm` at or above 60 min (`2h 14m`), else
`Mm` (`12m`, `0m`).

**Gauge.** Scale 0…1.25·`swap_rh`. Zones: DRY below `arm_rh` (green);
RISING from `arm_rh` up to `swap_rh − (swap_rh − arm_rh)/3` (amber); HIGH
from there to `swap_rh` (amber; the amber zone is lit for both); OVER at or
above `swap_rh` (red). Only the current zone is bright, others dim. Marker
at the reading, clamped to the bar. NaN: no marker, no word, `--% RH` dim.
HIGH is a display-only rule; its fraction is one constant in the header.

**Status strip.** Priority: fault → red fill, black `f_status_b`,
`"FAULT · " + fault_message`. Else if `uptime_ms < 60000` and the IP is
non-empty → the IP address. Else `status_text` (already "Disabled",
"Starting", "Air via A, B heating (waiting)" and so on).

**SIM badge** whenever `sim_enabled` is on. Never persisted (unchanged).

## 6. Controller change (`base.yaml`)

- New globals: `standby_elapsed_s` (float, `restore_value: true`) and
  `standby_state_seen` (int, `restore_value: true`, initial −1).
- In the control tick, right after the scaled `dt` is computed and before
  the first-run branch: if `standby_state != standby_state_seen`, set
  `standby_elapsed_s = 0` and `standby_state_seen = standby_state`; else
  `standby_elapsed_s += dt`. This catches every transition, including the
  ones made by `do_swap`, the fault paths and `Dryer Enabled` off, without
  touching each site.
- `reset_regen_counters` also zeroes `standby_elapsed_s`, so a regen that
  restarts after a reboot or Clear Fault shows the restarted time.
- New diagnostic sensor "Standby Phase Time" (min, one decimal, 10 s
  update), next to "Standby Heater Time".
- `docs/control-logic.md` counter table gains the row.

Nothing else in the state machine changes; `esphome config` before and after,
normalised, must differ only by these additions.

## 7. Preview build

`desiccant-dryer-preview.yaml`:

```yaml
substitutions: { name: desiccant-dryer-preview, friendly_name: Desiccant Dryer Preview }
esphome: { name: ${name} }
host:
logger:
packages:
  ui: !include packages/display-ui.yaml
  preview: !include packages/display-preview.yaml
```

`display-preview.yaml` provides every id the `ui_draw` script reads, as
globals and `template` switches, numbers, sensors and text sensors with the
same ids as the real build, plus an `sdl` display with `id: lcd`, 240×240,
`update_interval: 1s`, the same one-line lambda, and `window_options:
position` fixed so screenshots can be taken by region. An `on_boot` lambda
reads the `SCENARIO` environment variable (default 3) and loads one row of a
twelve-row table matching `docs/display/mockup-states.html`:

| # | Scenario |
|---|---|
| 1 | Starting: enabled, `active_pack` 0, both 24 °C, RH 1.1 |
| 2 | A in service, B WET, 26/25 °C, RH 2.4 |
| 3 | A in service, B HEATING, 31/87 °C, RH 6.8, fan on |
| 4 | A in service, B COOLING, 33/62 °C, RH 7.9 |
| 5 | A in service, B READY, 34/38 °C, RH 8.6 |
| 6 | A in service, B HEATING, RH 11.2 (OVER, waiting) |
| 7 | A in service, B COOLING, RH 9.1 (HIGH) |
| 8 | B in service, A HEATING, 94/29 °C, RH 5.6 |
| 9 | Fault 2, B at 124 °C, strip "FAULT · Standby pack overtemp" |
| 10 | Disabled, 28/45 °C |
| 11 | Boot: uptime under 60 s, strip shows 10.42.14.100 |
| 12 | Probe B NaN, SIM on, heater blocked |

The stub sets the switch states directly (valve A open and so on); there is
no state machine on the host. Every host run starts at uptime zero, so the
boot-IP rule would fire in every scenario; the stub therefore publishes an
empty `ip_addr` in all scenarios except 11, where it publishes
`10.42.14.100`.

`scripts/preview-shots.sh`: `esphome compile` the preview once, then for
each scenario run the built binary with `SCENARIO=n`, wait for the window,
`screencapture -R x,y,240,240 docs/display/state-nn.png`, kill it.
Requires macOS and `brew install sdl2`; documented in `docs/virtual-testing.md`.

## 8. Verification

1. `esphome config` on all three top-level files (validates YAML, fetches
   fonts and the MDI icon, rasterises the SVGs).
2. `esphome compile` real and virtual builds, as CI does. Add
   `esphome config` of the preview to CI if it validates on Linux without
   SDL headers; otherwise note it as local-only.
3. `scripts/preview-shots.sh`; compare the twelve PNGs to the mockup
   sheet; fix until they match; commit them.
4. Normalised `esphome config` diff of the real build before and after:
   outside the display, font, image and script sections, only the §6
   additions appear.
5. Flash the virtual build to the bench board to confirm the frame buffer
   still allocates and check the log for "took a long time" warnings from
   the display component. Waits for the user's go-ahead because the board
   is running the overnight soak.
6. Update `CLAUDE.md` (layout section, display package split, preview
   build) and `docs/virtual-testing.md`.

## 9. Risks and follow-ups

- Full-frame redraw time on the single-core S2 is unmeasured: about 58 k
  pixel writes for the background blit plus the SPI flush. If the display
  component logs slow-loop warnings, the follow-up is to draw the
  background only when a state input changes and let the driver flush the
  smaller dirty window.
- Google Fonts and the MDI icon are fetched at compile time; CI already
  depends on the network for Roboto today.
- The SVG art and the header share coordinates by hand. §2 is the single
  table both are written from; a mismatch shows up immediately in the
  preview screenshots.
- SDL preview is macOS-only as scripted; the yaml itself is portable.
